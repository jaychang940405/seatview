# 臺北大巨蛋（近似模型）

> 本模型為依公開報導與棒球規則推算的近似模型，非官方圖面；區、排、號為模型內部編號，不對應實際票面，不應作為購票依據。

- 資料：`src/venues/taipei-dome.json`（**不要手改**，由 `npm run gen:dome` 產生）
- 常數與等級：`scripts/taipei-dome-model.ts` 的 `K`（每個常數附 `{ value, grade, source }`，並輸出到 JSON 的 `meta.provenance`）
- 看台幾何與擬合：`scripts/dome-layout.ts`、`scripts/outline.ts`；重跑擬合：`npm run fit:dome`
- 不變量測試：`src/venues/taipei-dome.invariants.test.ts`；分析腳本的測試：`scripts/*.test.ts`
- 平面圖：[dome-plan-b.svg](screenshots/dome-plan-b.svg)（`npm run fit:dome -- --svg <檔案>` 產生）

## 數字等級

| 等級 | 意思 | 能不能當事實寫 |
|---|---|---|
| **A** | 規則或官方定義 | 可以 |
| **B** | 新聞報導的數字，非官方圖面 | 要附來源，註明是報導 |
| **C** | 本專案自己估的 | **不行**，只能寫成「估算」 |

## 建模範圍與席數

- 只建公開資料能錨定的範圍：內野一層、內野二層、外野一層，以及演唱會的暫定搖滾區 F1–F3。
- 總席位約 40,000（B）。其餘約 1.8 萬席（外野二層、包廂、場內近場席等）**不建模**，查詢時回 `UNKNOWN_SECTION`，不為了「完整」編資料。

| | 模型席數 | 報導推算的錨點（B） | 比例 |
|---|---|---|---|
| 一層（內野一層＋外野一層） | 15,351 | 約 17,000 | **約為報導推算值的 90%** |
| 二層（內野二層） | 4,690 | 約 4,700 | 約 100% |

一層的差距來自**外框淨空限制與未建模的樓層結構**：看台必須離圓頂外框 3 m 以上，而真實場館用多層看台往上疊，模型只建了兩層。模型席數只是估算，**不代表已湊齊錨點**。

## 座標約定

- 單位 m；Y 向上；場地 y = 0。
- 平面 (x, z)：x 向右、z 向下；角度 0° = +x、90° = +z。
- **原點 = 本壘板到中外野牆連線的中點**（C：為了方便而選）。
- 本壘板在 (0, 60.95)，中外野在 −z 側；一壘側在 +x、三壘側在 −x。
- 左右界外桿 = 本壘 + 102.11 ×（±sin 45°, −cos 45°）≈ (±72.20, −11.25)。

## 外框摘要（OpenStreetMap）

資料：© OpenStreetMap contributors，ODbL。用的是 OSM 圓頂分件 way 1304278778（`roof:shape=dome`），209.8 × 161.8 m。

- 看台應該在圓頂底下，所以用這個分件，而不是整棟建築的外框（227.1 × 168.7 m）。
- 本壘在圓頂的哪一端不知道（OSM 沒有畫球場），所以取**兩種本壘方位的交集**：外框和它繞面積形心轉 180° 的版本都要放得下。
- repo 裡**不放 OSM 座標**，只放擬合出的內接超橢圓：

| 參數 | 值 |
|---|---|
| 形狀 | \|x′/a\|ⁿ + \|z′/b\|ⁿ = 1，x′、z′ 為反向旋轉後的座標 |
| 半軸 a（x 方向） | 79.84 m |
| 半軸 b（z 方向） | 102.52 m |
| 指數 n | 2.5 |
| 旋轉 | 6.25° |
| 中心（模型座標） | (1, 6.95)，擺放位置是擬合結果（C） |
| 跟真實交集的最大內縮差距 | **0.95 m**（內接：每個方向都不超出真實外框） |

為什麼用超橢圓、不用方向極限值：

| 摘要方式 | 跟真實外框的最大差距 |
|---|---|
| 8 個方向的極限值連成八邊形 | 11.6–12.7 m（斜角削掉太多） |
| 16 個方向 | 3.8 m |
| **內接超橢圓（5 個形狀參數）** | **0.95 m** |

要從 OSM 重算：用 Overpass 匯出圓頂分件，再執行 `npm run fit:dome -- --osm <檔案>`。指令只印出結果，不寫檔。

## 方案 B 的看台（12 個區都是模型分區）

**幾何**：

- 本壘後方：以本壘為圓心的弧，45° → 135°。
- 一壘、三壘側：平行界外線的直線看台，從本壘後方弧的端點沿界外線往外野延伸。
- 外野：跟外野牆同心的弧，第一排離外野牆 3 m。
- 內野二層：懸挑在內野一層後段的上方，起始高度 = 一層最後一排高度 + 2.5 m。
  - 資料標成 `structure: "tier"`（懸挑樓板，下方是空的）；其他區用預設的 `solid`（實心到地面）。

**座號方向（我們採用的慣例，不是驗證）**：

- 內野（I1-*、I2-*）面向場地時，座號往左增加。所以一壘側從界外桿那端編起，三壘側從本壘端編起，本壘後方從一壘側編到三壘側。
- 依據只有本人坐過的 113 區與相鄰 114 區的照片，其餘各區沒有證據；不代表官方票區的真實座號方向。
- 外野（O1-*）的方向待查，目前沒有照片證據。
- 測試：`src/venues/taipei-dome.seat-order.test.ts`。每一排相鄰座位 s → s+1 的位移，在座位左手邊方向的分量必須 > 0；外野列為 todo。

**擬合的優先順序**：

1. 所有座位都在外框內，含 3 m 留空（必要）。
2. 一層 ≤ 30 排（必要）。
3. 席數不超過錨點 +10%（必要），並盡量落在 ±10% 內、越接近錨點越好。

| **3 m（採用）** | **15,351（−9.7%）** | **4,690** | **是** |
| 5 m | 14,266（−16.1%） | 4,705 | 否 |

## Layouts

### baseball（棒球）

- **focus**：(0, 0.8, 60.95)，`facingDeg` = 90（朝本壘後方）。位置是本壘板（B，由距離推算），高度 0.8 m 是好球帶中心的估算（C）。
- **水平偏角的意義**：0° = 本壘正後方；一壘側為正、三壘側為負；右外野 +90° 到 +180°，左外野 −90° 到 −180°，中外野 ±180°。
- **overlays**（全部由 A／B 級常數產生）：
  - 界外線：本壘 → 左右界外桿。
  - 外野牆：通過左桿、中外野點、右桿的圓弧，每 5° 取點；不建牆高。
  - 內野：本壘 → 一壘 → 二壘 → 三壘，closed。
  - 投手丘：box。

### concert（演唱會（暫定假設：外野端台））

- **舞台的位置、尺寸、高度整個都是假設**，每場演出不同，不是場館的屬性。
  - focus：(0, 3.5, −50)，`facingDeg` = 90。
  - stage：中心 (0, 1, −50)，尺寸 40 × 2 × 16 m。
- **開放範圍**：I1-*、I2-*、O1-RF、O1-LF、F1–F3。O1-CF 在舞台後方，不開放。
- 舞台資料更新時，只改 `K` 的舞台、concert focus、搖滾區，再重新產生 JSON。

### 分析腳本的測試（`scripts/*.test.ts`）

- **左右對稱**：
  - 外框左右對稱時，一壘、三壘兩側直線看台的最大長度相等，外野左右兩區的排數相等，擬合出的外框中心在 x = 0。
  - 外框旋轉 +θ 與 −θ 時，左右結果互換。
- **座位數雙算法**：每區「逐排取整加總」和「看台面積 ÷ 每席面積」差距 < 2%；逐排加總也等於 core 實際列出的座位數。
- **aL 符號回歸**：左外野桿的角度必須是 −180° − 右桿（約 −159.1°），所有外野座位都要在外野牆外側、中外野那一邊。

### 敏感度

見 [sensitivity.md](sensitivity.md)：距離誤差主要來自一層前緣距離和外野淨空，本壘後方前排約 ±3 m（16%），中外野約 1%。

## 已知限制

- **看台形狀是簡化的**：本壘後方是圓弧、兩側是直線、外野是同心弧；真實的看台輪廓更複雜。
- **界外桿附近沒有座位**：外野左右兩區從界外桿往中外野內縮 32° 才開始。這是為了在外框內放進最多座位的擬合結果，不代表真實場館在那裡沒有座位。
- **一層比錨點少約 10%**：差距來自外框淨空限制與未建模的樓層結構。
- **二層只建在內野**：沒有外野二層。
- **二層懸挑的遮擋只在畫面上**：從一層後排抬頭看得到懸挑（[截圖](screenshots/p1-after-7-hp-r30-look-up.jpg)），但距離、角度數據沒有計算遮擋。
- **外框摘要的擺放位置是擬合出來的**：本壘的實際方位不知道，所以要求兩種方位都放得下。
- **沒有建模的部分**：牆高、屋頂、包廂、外野二層、場內近場席、其餘約 1.8 萬席；沒建的區查詢時回 `UNKNOWN_SECTION`。
- **舞台是暫定假設**：位置、尺寸、高度都不是場館資料。
- **編號不是真實票面**：區、排、號都是模型內部編號（模型分區），不對應官方票區、排號或座號。
