# 臺北大巨蛋（近似模型）

> 本模型為依公開報導與棒球規則推算的近似模型，非官方圖面；區、排、號為模型內部編號，不對應實際票面，不應作為購票依據。

- 資料：`src/venues/taipei-dome.json`（**不要手改**，由 `npm run gen:dome` 產生）
- 產生器與所有常數：`scripts/gen-taipei-dome.ts`（每個常數都附 `{ value, grade, source }`，並輸出到 JSON 的 `meta.provenance`）
- 不變量測試：`src/venues/taipei-dome.invariants.test.ts`

## 數字等級

| 等級 | 意思 | 能不能當事實寫 |
|---|---|---|
| **A** | 規則或官方定義 | 可以 |
| **B** | 新聞報導的數字，非官方圖面 | 要附來源，註明是報導 |
| **C** | 本專案自己估的 | **不行**，只能寫成「估算」 |

## 建模範圍

- **只建公開資料能錨定的範圍**：內野一層、內野二層、外野一層（棒球時合計 21,660 席），以及演唱會的暫定搖滾區 F1–F3。
- 總席位約 40,000（B）。其餘約 1.8 萬席（外野二層、包廂、場內近場席等）**不建模**，查詢時回 `UNKNOWN_SECTION`，不為了「完整」編資料。

## 座標約定

- 單位 m；Y 向上；場地 y = 0。
- 平面 (x, z)：x 向右、z 向下；角度 0° = +x、90° = +z。
- **原點 = 本壘板到中外野牆連線的中點**（C：為了方便而選，視為看台中心的近似）。
- 本壘板在 (0, 60.95)，中外野在 −z 側；一壘側在 +x、三壘側在 −x。
- 左右界外桿 = 本壘 + 102.11 ×（±sin 45°, −cos 45°）≈ (±72.20, −11.25)。

## 分區與參數（全部 C 級估算，除非另註）

所有 arc 區：`center = (0, 0)`、`rowDepth = 0.85`。每排席數與該排弧長成正比，縮放到目標席數，最後一排吸收取整誤差；隱含座位間距必須落在 0.45–0.65 m，否則產生器報錯。

## Layouts

### baseball（棒球）

- **focus**：(0, 0.8, 60.95)，`facingDeg` = 90（朝本壘後方）。
  - 位置是本壘板（B，由距離推算）。
  - 高度 0.8 m 是好球帶中心的估算（C）。
- **水平偏角的意義**：
  - 0° = 本壘正後方；一壘側為正、三壘側為負。
  - 右外野 +90° 到 +180°，左外野 −90° 到 −180°，中外野 ±180°。
- **overlays**（全部由 A／B 級常數產生）：
  - 界外線：本壘 → 左右界外桿。
  - 外野牆：通過左桿、中外野點 (0, −60.95)、右桿的圓弧，每 5° 取點。不建牆高。
  - 內野：本壘 → 一壘 → 二壘 → 三壘，closed。
  - 投手丘：box，中心在本壘前 18.44 m。

### concert（演唱會（暫定假設：外野端台））

- **舞台的位置、尺寸、高度整個都是假設**。每場演出不同，這不是場館的屬性，之後會用實際擺位資料更新。
  - focus：(0, 3.5, −50)，`facingDeg` = 90，也就是舞台面朝內野看台。3.5 m = 舞台高 2 m 加表演者視線約 1.5 m。
  - overlay：`stage`，中心 (0, 1, −50)，尺寸 40 × 2 × 16 m。
- **開放範圍**：`I1-*`、`I2-*`、`O1-RF`、`O1-LF`、`F1–F3`。`O1-CF` 在舞台後方，不開放。
- 舞台資料更新時，**只改產生器裡的常數**（舞台、concert focus、搖滾區），再重新產生 JSON；不改 core 或 render 的程式碼。

**突變檢查**：故意改壞產生器的常數，確認不變量真的會失敗：

| 突變 | 結果 |
|---|---|
| O1 半徑 78 → 74 | 外野牆淨空失敗 |
| I2 高度 14 → 8 | 高度關係失敗 |
| 內野分區 −9 → −20（跟外野重疊） | 不重疊失敗 |
| I1 每區 3150 → 3500 | 兩項席數失敗 |

### OpenStreetMap 外框檢查

資料：© OpenStreetMap contributors，ODbL；way 442195153「臺北大巨蛋」（`building=stadium`），Overpass API，資料時間 2026-10-22T17:52Z。

量測方法：
- 以形心為原點，用等距圓柱近似把經緯度換算成公尺。
- 每 1° 量一次外框的投影寬度。

| | OSM 建築外框 | 模型看台（座位中心） |
|---|---|---|
| 長向寬度 | 227.1 m | 沿本壘–中外野軸 195.9 m（−90.8 → +105.1） |
| 短向寬度 | **168.7 m** | 橫向 **210.2 m**（二層外半徑 105.1 m × 2）；只算一層也有 185.5 m |
| 中心到外框的距離 | 83.4–116.5 m | 看台半徑 78–105.1 m |
| 面積 | 31,967 m²（等效圓直徑 201.7 m） | — |

**結論：二層外半徑和看台的整體寬度不合理。** 看台是以原點為圓心的正圓，但建築外框是扁的。不論球場軸線怎麼擺，模型在短向都超出外框，大約每側 20 m。

模型的數值暫時保留作為 C 級估算起點，修正方向待決定（見下節）。這裡只引用 OSM 來檢查合理性，沒有把 OSM 的數字寫進模型。

## 已知限制

- **用圓弧近似看台**：實際的看台比較接近橢圓。OSM 檢查顯示，模型在短向比建築外框寬約 41 m（見上節）。影響最大的是一壘側、三壘側靠近 0° 和 180° 的座位，它們離球場軸線太遠，距離與角度都會偏大。
- **沒有建模的部分**：
  - 牆高、屋頂、包廂、外野二層、場內近場席。
  - 其餘約 1.8 萬席。
  - 沒建的區查詢時回 `UNKNOWN_SECTION`。
- **舞台是暫定假設**：位置、尺寸、高度都不是場館資料，每場演出不同。
- **編號不是真實票面**：區、排、號都是模型內部編號，不對應官方票區、排號或座號。
- **其他簡化**：
  - 每區斜度固定（`rowRise`）。
  - 沒有走道、遮蔽判斷、字母排號、單雙號分邊。
  - 外野牆只是平面上的線，沒有高度，所以外野看台的視線不會被牆擋住。
